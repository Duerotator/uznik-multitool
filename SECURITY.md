# Политика безопасности

## Поддерживаемая версия

Исправления безопасности выпускаются для текущей ветки `main`. Старые коммиты
и сторонние сборки отдельно не поддерживаются. Перед сообщением проверьте,
воспроизводится ли проблема на актуальном коммите, не используя рабочие аккаунты.

## Сообщить об уязвимости

Используйте [приватное сообщение GitHub Security Advisory](https://github.com/Duerotator/uznik-multitool/security/advisories/new).
Не публикуйте уязвимости с доступом к чужим аккаунтам в обычном Issue до исправления.

Укажите коммит, ОС, версию Python, затронутую функцию, ожидаемый риск и минимальные
шаги воспроизведения на фиктивных данных. Удалите из отчёта пароли, токены,
session strings, файлы `.session`, почтовые списки и браузерные профили.
Срок исправления зависит от воспроизводимости и серьёзности; гарантированного SLA нет.

При утечке Telegram-сессии завершите соответствующие авторизации в официальном
Telegram, смените скомпрометированные пароли и отзовите API-токены. Удаление
файла или коммита само по себе не отзывает доступ.

## Что проверяется

Публичные workflow выполняют CodeQL, Bandit, аудит Python-зависимостей и
автономные тесты. GitHub secret scanning и push protection помогают обнаружить
поддерживаемые форматы секретов. Они не распознают все пароли или личные данные.
Успешная проверка не гарантирует отсутствие вредоносного поведения или ошибок.

Хранение данных, сетевые подключения и обзор установщика:
[SECURITY_AND_DATA](docs/SECURITY_AND_DATA.md). Проверка исходного архива:
[RELEASES](docs/RELEASES.md).
