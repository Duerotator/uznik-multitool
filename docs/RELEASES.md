# Проверка и подготовка релизов

## Для пользователей

Проект распространяется как исходный код, не как подписанный `.exe`.
На [странице Releases](https://github.com/Duerotator/uznik-multitool/releases)
проверяемый релиз должен содержать `*-source.zip`, `SHA256SUMS.txt` и
`provenance.json`. Если таких релизов ещё нет, используйте Git и проверяйте
коммит; обычный GitHub Download ZIP не получает нашу attestation автоматически.

Сравните SHA-256 скачанного ZIP с `SHA256SUMS.txt`:

```powershell
Get-FileHash .\uznik-multitool-<commit>-source.zip -Algorithm SHA256
```

Это проверка целостности, а не доказательство безопасности. Подлинность
происхождения проверяется отдельно через [GitHub CLI](https://cli.github.com/):

```powershell
gh attestation verify .\uznik-multitool-<commit>-source.zip --repo Duerotator/uznik-multitool
```

Проверьте, что attestation относится к workflow `.github/workflows/release.yml`
этого репозитория и нужному коммиту. Коммит и Git tree указаны в `provenance.json`
и `BUILD_INFO.json` внутри архива. Проверяйте также результаты Security checks
и CodeQL для этого коммита. Attestation подтверждает происхождение сборки,
а не отсутствие уязвимостей. SHA-256 сам по себе не защищает от подмены обоих файлов.

## Для сопровождающих

1. Проверьте изменения и результаты CI, выполните автономные тесты.
2. Создайте и отправьте осознанно выбранный тег `vMAJOR.MINOR.PATCH` на проверенный
   коммит. Тег должен включать release builder и актуальную лицензию.
3. В Actions запустите **Source release** из `main`, указав существующий тег.
   Workflow проверит, что тег указывает на коммит запущенного workflow.
4. Проверьте созданный **черновик** релиза, ZIP, checksum и attestation, затем
   опубликуйте вручную. Уже существующий релиз workflow не перезаписывает.

Builder берёт файлы через `git archive` из указанного коммита, а не копирует
рабочую папку. Неотслеживаемые `.env`, ящики, сессии и базы не попадают в архив.
Если чувствительный runtime-файл оказался отслеживаемым, сборка останавливается;
ссылки и специальные файлы также отклоняются. Это дополнительная проверка путей,
не полноценное распознавание секретов внутри произвольных исходников.

Локальная сборка не создаёт GitHub attestation и не публикует релиз:

```powershell
.\.venv\Scripts\python.exe scripts/releases/build_source_release.py --ref HEAD
```

Результат — в `dist/source/`, исключённом из Git. Пакеты Python и внешние
программы не включаются: устанавливаются отдельно. Архив не является lockfile
зависимостей. Лицензии сторонних компонентов остаются их собственными.
