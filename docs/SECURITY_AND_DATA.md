# Данные, подключения и проверка исходников

Uznik MultiTool — приложение с доступом к Telegram-аккаунтам и локальным TON/WalletTg
инструментам. До установки проверьте исходники и зависимости; используйте только
аккаунты, которыми вправе управлять. Проект не является официальным клиентом Telegram,
не обещает обхода его ограничений и не гарантирует «100% безопасность».

## Локальные данные

| Место | Содержимое и риск |
| --- | --- |
| `.env` | Telegram API-ключи, настройки интеграций, флаги `TGB_FINANCE_*` и при указании пароль 2FA / токен MarketApp |
| `data/accounts.json` | Метаданные аккаунтов; могут содержать email и поля совместимости 2FA |
| `data/sessions/`, исходные сессии в `imports/` | Авторизации Telegram; копирование позволяет получить доступ к аккаунту |
| `data/browser_profiles/` | Постоянные профили Chromium с авторизацией Telegram Web |
| `data/passkeys/` | Материалы ключей доступа; требуют защиты как пароль |
| `data/secret_vault/`, `data/marketapp_credentials/` | Зашифрованные хранилища 2FA-паролей аккаунтов и токена MarketApp |
| `data/financial_keys/vault.sqlite3` | Зашифрованное хранилище TON/WalletTg ключей, защищённое DPAPI / мастер-паролем |
| `data/finance_money.sqlite3`, `data/assets_readonly.sqlite3` | Локальный журнал финансовых намерений/карусели, бюджеты и кэш read-only TON-активов |
| `data/wallet_addresses.json`, `data/wallet_addresses.txt` | Экспортированная сводка адресов кошельков аккаунтов |
| `data/profile_recipes.sqlite3`, `data/task_history.sqlite3`, `data/warmup_state.sqlite3` | Базы рецептов профилей, истории задач и состояния прогрева/ограничений |
| `imports/emails/accounts.txt` | Ваш список почтовых логинов и паролей; хранится в открытом текстовом виде |
| `data/email_mailbox_bindings.json` | Закрепления ящиков за аккаунтами, без паролей |
| `data/webshare_accounts.json`, `data/proxy_pool.db` | Ключи Webshare и реквизиты пользовательских прокси; требуют защиты |
| `data/profiles_archive/`, другие кэши | Сохранённые профили, изображения, видео и результаты проверок |
| `data/resumable_jobs.json`, `data/story_publications.json` | Исходные ID и параметры пакетов; хеши медиа и подтверждения публикаций, без паролей |
| `*.uzbk`, `data/backups/` | Зашифрованные копии сессий, API-ключей, почт и других личных данных; требуют отдельного пароля |
| `templates/profile_plan.json`, `profile_plan.json.key` | Зашифрованный план профилей и его ключ; на Windows ключ привязан к пользователю через DPAPI |
| `data/logs/`, `_local/` | Локальная диагностика, отчёты и вспомогательные личные скрипты; могут содержать ID, ошибки или локальные пути |

Приложение не обеспечивает общего шифрования всех файлов на диске. `.gitignore`
исключает рабочие данные, `.env`, `node_modules/`, `unknown_errors.txt` и `_local/`
из обычного Git-добавления, но не шифрует их и не защищает от других пользователей
компьютера, резервного копирования или `git add -f`. Используйте права доступа ОС,
шифрование диска и защищённые резервные копии. Не отправляйте рабочий каталог целиком
в публичные отчёты.

Копии **Tasks / Backups** шифруются AES-256-GCM; ключ получается из отдельного
пароля через PBKDF2-HMAC-SHA256 (600000 итераций, случайная соль). Проверка
аутентичности и содержимого выполняется до замены данных. Пароль не сохраняется.
При подготовке/восстановлении используются временные незашифрованные файлы:
защищайте системный временный каталог и диск средствами ОС. Это шифрование
копий, а не всей рабочей базы. `.uzbk` исключены из Git и исходных релизов.
Состав, исключения и правила переноса описаны в [RECOVERY](RECOVERY.md).

Финансовое хранилище (`data/financial_keys/vault.sqlite3`) и хранилища секретов
(`SecretVault` / `MarketappCredentials`) шифруют записи отдельно от общей базы
аккаунтов и защищаются на Windows через DPAPI текущего пользователя и/или отдельный
мастер-пароль. Портативные копии `financial_backup` шифруются отдельным паролем;
CLI-администрирование доступно через `scripts/manage_financial_vault.py`.

## Сетевые подключения

| Функция | Что передаётся и кому |
| --- | --- |
| Работа с аккаунтами | Запросы MTProto серверам Telegram; без прокси виден ваш IP |
| Open acc | Авторизация и действия в `web.telegram.org` через Chromium |
| Прокси / Xray | Трафик идёт через настроенного вами провайдера; пользовательские источники прокси и VPN-подписки запрашиваются при соответствующих действиях |
| Webshare | При настроенной интеграции API-ключ передаётся `proxy.webshare.io` для получения ваших прокси |
| IMAP / POP3 | Логин и пароль выбранному почтовому серверу по TLS; читаются сообщения для получения кода, отправка почты не используется |
| HTTP inbox | Адрес ящика, параметры поиска кода и настроенный токен вашему inbox API |
| AI-диалоги | Настроенному AI-провайдеру отправляются запрос, контекст диалога и имена участников; не включайте функцию для конфиденциальных чатов |
| Розыгрыши / Mini Apps | Сайтам выбранного розыгрыша передаются данные Telegram WebApp и запросы участия; это сторонние сервисы, не только Telegram |
| Внешний OCR | При использовании SolveCaptcha передаются изображение капчи и API-ключ этому сервису; локальный OCR не требует этого ключа |
| TON / WalletTg / TonCenter | Публичные запросы чтения/эмуляции/отправки BOC на `toncenter.com` / `testnet.toncenter.com` (только публичные адреса и подписанные внешние сообщения; сид-фраза остаётся локальной); для нативных переводов mainnet нужны явные флаги `TGB_FINANCE_ENABLE_NATIVE=1` и `TGB_FINANCE_ENABLE_MAINNET=1` |
| MarketApp | При явном подтверждении чтение каталога/аренды на `api.marketapp.org` с токеном из выделенного vault или `MARKETAPP_API_TOKEN` |
| Загрузка ресурсов | Указанному вами источнику отправляется запрос на скачивание ресурсов |

Внешние интеграции настраиваются пользователем; участие, сообщения, финансовые
переводы и массовые действия могут изменять состояние аккаунтов или средств.
Не используйте рабочие сессии и непустые кошельки для непроверенных сценариев.
Настроенный неисправный прокси не обходится прямым подключением; при отсутствии
прокси прямое подключение разрешено.

## Установщик и права

`setup.bat` запускает читаемый `scripts/setup.ps1`. Он создаёт `.venv`,
устанавливает Python-пакеты из PyPI, скачивает Playwright Chromium и устанавливает
отсутствующие FFmpeg, Tesseract и Xray через WinGet. Источники и точные WinGet ID
описаны в [INSTALLATION](INSTALLATION.md). Для TON/WalletTg кодека дополнительно
используются Node.js и локальные npm-зависимости в `app/ui/finance/`. Установка
внешних программ может запрашивать UAC. Для обычной работы приложения права
администратора не требуются.

`-ExecutionPolicy Bypass` относится к запускаемому процессу PowerShell, а не к
постоянному изменению политики компьютера. Скрипт создаёт `.env`, если его нет,
папки данных и ярлыки; не устанавливает службу приложения. Установка Xray не
включает gateway автоматически. Вариант `-SkipNativeTools` пропускает WinGet.

## Где проверять поведение

- `scripts/setup.ps1`, `scripts/windows/install_native_tools.ps1` — установка.
- `app/core/config.py`, `app/core/project_layout.py` — настройки и пути данных.
- `app/modules/direct_access.py`, `session_onboarding.py` — браузер и авторизация.
- `app/modules/email_inbox.py`, `email_mailbox.py` — чтение почтовых кодов.
- `app/modules/ai_companion.py`, `raffle_*.py`, `vpn_gateway.py` — внешние интеграции.
- `app/modules/financial_vault.py`, `wallet_tg_codec.py`, `money_*.py`, `marketapp_*.py` — финансы и MarketApp.
- `.github/workflows/` — команды публичных проверок (Bandit, TruffleHog, pip/npm аудит, CodeQL, тесты) и подготовки релиза.

Проверяйте результат workflow именно для скачанного коммита: значок в README
показывает состояние ветки, а не всех версий. Bandit и CodeQL ищут определённые
классы ошибок; `pip-audit` и `npm audit` проверяют опубликованные сведения об
уязвимостях, а не все риски цепочки поставки. Тесты используют фиктивные данные и
не входят в Telegram. Проверки не заменяют независимый аудит. Отчёты могут содержать
предупреждения даже при успешном workflow; политика порога описана в самом workflow.

### Защита плана и минимизация логов

План профилей сохраняется с аутентифицированным шифрованием Fernet. На Windows
ключ защищён DPAPI текущего пользователя, без отключения защиты при ошибке.
На других ОС ключ хранится отдельным файлом с правами `0600`; это не защищает
от процесса того же пользователя, получившего доступ к обоим файлам.
Старые JSON-планы автоматически шифруются при успешной загрузке. Для резервной
копии нужны и план, и ключ; перенос Windows-плана к другому пользователю без
расшифровки исходным пользователем не поддерживается. При потере ключа восстановить
план невозможно. Текстовые экспорты шаблонов остаются открытыми — защищайте их
как другие пользовательские файлы. Это не шифрует всю базу, сессии или архивы.

Ошибки входа и сообщения очереди не выводят номер телефона; успешное применение
дня рождения не записывает его значения. Части API-ключей Webshare также не
выводятся. Другие логи всё ещё могут содержать ID аккаунта, имя или адрес почты:
перед публикацией очищайте их от персональных данных.
