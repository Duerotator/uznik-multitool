# Продолжение задач и резервные копии

## Продолжить пакет

В **Tasks / Backups → Resume batch…** выберите сохранённый пакет и подтвердите
запуск. Поддерживаются **Check sessions**, **Check spamblock** и **Apply saved
profiles**. Для них список ID, исходная группа, параметры и результаты каждого
аккаунта записываются в `data/resumable_jobs.json`.

Завершённые аккаунты пропускаются. Неудачные, прерванные и ещё не обработанные
проверяются повторно. Текущие фильтры не заменяют исходную область задачи;
новые аккаунты не добавляются вместо удалённых или отключённых. Вторая ручная
задача не запускается одновременно. После аварии приложение ничего не начинает
без подтверждения пользователя. Смена паролей/email и другие операции с
секретами не поддерживают этот способ продолжения.

При частичном **Apply saved profiles** выбранный профиль остаётся закреплён
за тем же аккаунтом. Повторный запуск может снова применить его поля/аватары,
но учитывает подтверждённые публикации историй отдельно.

## Учёт историй

`data/story_publications.json` хранит SHA-256 каждого медиа, ID публикации,
статус и заранее сохранённый `random_id`. Успех фиксируется после ответа
Telegram с ID истории; пустой ответ не считается успешной публикацией.
Перестановка архива и ошибка в середине списка не приводят к пропуску хвоста.
При неопределённом результате повтор использует тот же `random_id`:
[контракт Telegram SendStory](https://core.telegram.org/method/stories.sendStory).
Это не обещание бессрочной серверной дедупликации при любых обстоятельствах.

Для старых записей с одним `stories_uploaded` приложение просит подтверждение:
первые N историй архива действительно должны соответствовать опубликованным
в исходном порядке. Если порядок неизвестен или раньше были ошибки, **не
подтверждайте** — требуется сверка, иначе возможны пропуски. Нельзя вычислить
соответствие старых публикаций по одному счётчику. Архив и учёт публикаций
следует переносить вместе. Telethon пока не поддерживает публикацию историй
и профильную музыку в этом приложении; вместо ложного успеха выводится ошибка.

## Создать копию

**Tasks / Backups → Create backup…**: выберите новый файл `.uzbk` и отдельный
пароль не короче 10 символов. Рекомендуется длинный случайный пароль;
храните его отдельно. Приложение его не запоминает и не может восстановить.
Копия содержит авторизации и секреты; не публикуйте её вместе с паролем.

В копию входят настроенные `data/` и `imports/`, `.env`, пользовательские
`templates/`, `assets/avatar_packs/` и `sessions/batch_phones.txt`. SQLite
сохраняется через согласованный snapshot, включая закоммиченный WAL.
Исключены логи, браузерные авторизации, gateway runtime, предыдущие копии,
активные `tasks.json`, ссылки/junctions и исполняемые инструменты создания
сессий. Внешние файлы вне указанных каталогов не включаются. Максимальный
объём — 8 GiB и 50000 файлов. Закройте другие экземпляры MultiTool; текущая
ручная операция должна завершиться, а Warmup / Online будут остановлены.
После создания копии фоновые режимы запускаются снова только вручную.

## Восстановить

1. Закройте другие экземпляры приложения и процессы, использующие эти сессии.
2. Нажмите **Restore backup…**, выберите файл и введите его пароль.
3. Приложение проверит шифрование, хеши и пути всех файлов, затем создаст
   `data/backups/before-restore-….uzbk` с текущими данными и тем же паролем.
4. Дождитесь завершения и перезапустите MultiTool.

Файлы из копии заменяют одноимённые файлы; дополнительные текущие файлы не
удаляются. Это восстановление с наложением, не очистка всех данных. При ошибке
замены выполняется откат; сохраните предварительную копию и лог ошибки.
Не прерывайте процесс и не выключайте компьютер во время восстановления.
Копия перед восстановлением не включает браузерный кэш и другие исключения.

При переносе между установками пути управляемых сессий и переменные
`TELEGRAM_DATA_DIR` / `TELEGRAM_IMPORT_DIR` адаптируются к принимающей установке.
Другие внешние пути в `.env` проверьте вручную. Windows-ключ плана профилей
защищён DPAPI: копирование файлов не делает его доступным другому пользователю
или компьютеру. Защита резервного архива не снимает это ограничение.

Копии шифруются на диске, но во время подготовки используются временные
незашифрованные файлы; нужна защита ОС и системного временного каталога.
При обычном завершении они удаляются, при аварии могут остаться. `.uzbk`
исключены из обычного Git и исходных релизов, но `git add -f` обходит `.gitignore`.
